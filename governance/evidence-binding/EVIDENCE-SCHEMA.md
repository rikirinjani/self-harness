## 1. Principle and Governance Directive

> **"Replace *'all files have appeared in some trace'* with: *'all changes in this revision have current evidence.'*"**
> — *GPT-6 Astra Governance Review*

Historical file-path matching (such as `tools/retrace.py` scanning trace records for matching file names or paths) checks only whether a file was touched at any point in history. It cannot establish:
1. Whether the **current content** of that file in the candidate revision was verified.
2. What exact command was executed against this revision.
3. Whether the tests passed with zero exit code.
4. Whether uncommitted changes or unstaged alterations contaminated the run.

Under this schema, **historical filename coverage is demoted to a hygiene inventory metric**. Release and merge gates evaluate **revision-bound evidence records** tied cryptographically to the base commit, head commit, and file blob hashes.

---

## 2. Machine-Observed vs. Agent-Asserted Segregation

To eliminate self-policing and prevent agents from certifying their own unverified claims, all fields are strictly partitioned into two disjoint namespaces:

| Classification | Meaning & Trust Boundary | Modification Authority |
|---|---|---|
| `agent_asserted` | Intent, routing labels, task explanations, agent/model identifiers. These are treated as **untrusted claims** submitted for recordkeeping. | Agent / Orchestrator |
| `machine_observed` | Cryptographic hashes, process exit codes, system timestamps, git commit SHAs, blob hashes, and seed environment capture. Captured directly by `run-evidence.py` via kernel/OS subprocess and git plumbing. | **Subprocess wrapper only** (Agent cannot edit) |

An evidence record where `agent_asserted.agent_id` claims `"PASS"` but `machine_observed.execution.exit_code != 0` is an immediate hard gate rejection.

Mapping onto the actual record: the `assertions` block is agent-asserted (task/run/agent/model
identity supplied on the command line); `capture`, `governance_config`, `repository`,
`revision`, `execution`, `environment`, `outputs`, and `output_fingerprint_sha256` are
machine-observed by the wrapper.

## 3. Evidence Record JSON Schema (as implemented by `run-evidence.py`)

Canonical evidence records are formatted with deterministic 2-space indentation, alphabetically sorted keys, POSIX newlines, and UTF-8 encoding (`json.dumps(..., sort_keys=True, ensure_ascii=True, allow_nan=False)` plus a trailing newline, then ASCII-encoded).

Record filename: `<assertions.run_id>.json`, stored under the evidence directory
(must be **outside** the worktree and outside `.git`).

### Top-level fields

| Field | Type | Class | Meaning |
|---|---|---|---|
| `schema_version` | int | machine | Must equal `SCHEMA_VERSION` (currently `1`). Unknown version ⇒ record rejected. |
| `record_type` | str | machine | Always `"revision-command-evidence"`. |
| `assertions` | object | **agent-asserted** | `task_id`, `run_id`, `parent_task_id`, `agent_id`, `model_id`, `governance_config_version` — all supplied by the invoking agent, untrusted. |
| `capture` | object | machine | `recorded_at` (UTC ISO-8601, microseconds), `wrapper_sha256` + `wrapper_bytes` (hash of the evidence wrapper itself, re-checked before and after execution). |
| `governance_config` | object | machine | `path`, `sha256`, `bytes` of the governance config; a change to it during execution aborts publication. |
| `repository` | object | machine | Repository identity (`id`, root) resolved by Git plumbing. |
| `revision` | object | machine | `base`, `head` (full SHAs), `base_is_ancestor: true`, `worktree_clean_before/after: true`, `changed_files` — re-verified after artifact capture; any drift aborts publication. |
| `execution` | object | machine | `command`, `exit_code`, `timed_out`, duration — observed by the subprocess wrapper. |
| `environment` | object | machine | `variables` (allow-list), `seed_variables` (SEED/TEST_SEED/RANDOM_SEED/PYTHONHASHSEED/HYPOTHESIS_SEED), `removed_inherited_git_variables`, `platform`, `python_version`, `git_version`. |
| `outputs` | object | machine | `stdout`, `stderr` (content-addressed object hashes), `log_artifacts[]` (`path` + `artifact` hash). |
| `output_fingerprint_sha256` | str | machine | SHA-256 over the canonical record minus the fingerprint field itself; recomputed on every read (`verify_record`). |

### Acceptance rules enforced by `verify_record` / `write_record`

1. `schema_version` must match the current `SCHEMA_VERSION`.
2. `repository.id` must match the expected repository; `revision.head` must match the expected revision.
3. Filename must equal `<assertions.run_id>.json`.
4. `output_fingerprint_sha256` must equal the recomputed fingerprint.
5. `execution.exit_code == 0` and `execution.timed_out == false` are required for a gate **pass**; a non-zero exit or timeout is a hard rejection regardless of any `agent_asserted` claim.
6. The record is written atomically (temp file + rename) with an advisory lock (`fcntl`), so concurrent runs cannot interleave partial records.

### Trust boundary

`run-evidence.py` is POSIX-only (uses `fcntl`), requires Python 3.10+ and Git, and must be
invoked outside the worker's control (CI or operator shell). An agent that can edit the
evidence directory can forge records; therefore the evidence directory must be writable by
the pipeline but not by the worker under review, and gates must verify fingerprints against
the published location rather than the worktree copy.
